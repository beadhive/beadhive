# Spike `bh-u562.3` — unified host transport and route composition

**Bead:** `bh-u562.3` · **Seat:** `dev/u562-http` · **Type:** research-only (no product code)
**Feeds decision on:** `bh-u562.5`, the unified Beadhive host-daemon contract and its
implementation epic

## Question

Can the current `build_server()` FastMCP surface be offered unchanged at `/mcp` over
Streamable HTTP, while existing stdio registrations continue to work, and can one ASGI process
also own versioned operator REST/SSE, OpenAPI, health, and terminal WebSocket routes without
making MCP JSON-RPC the browser protocol?

This spike tests transport and composition only. It does **not** implement authoritative bead or
run projections, event retention, a PTY, container exec, production auth, daemon supervision, or
telemetry.

## Evidence

1. **Every currently registered MCP tool has exact real-client parity.** The test discovers the
   tool list rather than trusting the molecule's stale count of eleven. There are ten today.
   It compares every input schema and every normalized success payload or `ToolError` byte-for-
   byte between a spawned stdio client and a spawned HTTP client
   (`tests/spikes/test_bh_u562_3_unified_host_transport.py:27-40,110-144`). The safe inputs either
   read, dry-run, or deliberately fail validation before mutation.

   | current tool | inert-call result over stdio | stateless HTTP | session HTTP |
   |---|---|---|---|
   | `plan_check` | structured success | exact parity | exact parity |
   | `plan_file` | clean validation `ToolError` | exact parity | exact parity |
   | `work_refine` | clean dry-run `ToolError` | exact parity | exact parity |
   | `bd_create` | `{created: [], count: 0}` | exact parity | exact parity |
   | `hive_list` | structured success | exact parity | exact parity |
   | `config_set` | structured validation refusal (`ok: false`) | exact parity | exact parity |
   | `hive_add` | clean required-field `ToolError` | exact parity | exact parity |
   | `hive_onboard` | clean required-field `ToolError` | exact parity | exact parity |
   | `hive_status` | structured success | exact parity | exact parity |
   | `toolchain_exec` | clean empty-argv `ToolError` | exact parity | exact parity |

   This reuses the sole product registrar (`src/beadhive/mcp.py:491-528`). The existing stdio
   entry point still calls that same builder (`src/beadhive/mcp.py:1130-1142`), so HTTP is an
   additional adapter, not a forked tool registry.

2. **One ASGI route table and lifespan can own all candidate paths.** The proof directly adds
   FastMCP's generated `/mcp` route after `/health`, `/api/v1/factory`, hive snapshot/SSE, run
   activity, `/ws/terminal`, and `/openapi.json`; its lifespan enters `mcp_app.lifespan`
   (`proofs/bh_u562_3_unified_host_transport.py:218-258`). All paths answered in the same spawned
   Uvicorn process. `/mcp` remained MCP Streamable HTTP; browser-facing handlers remained ordinary
   JSON, SSE, or WebSocket protocols.

3. **Both MCP HTTP modes work, but they do not have the same continuity contract.** All ten tool
   calls passed with `stateless_http=True` and `False`. The real client observed no session ID in
   stateless mode and a session ID in session mode (`tests/...:125-142`). No current **tool** needs
   cross-call session state. However, the existing MCP surface also advertises resource
   subscriptions and mutation-driven `resources/updated` notifications. FastMCP stateless mode
   creates a fresh transport per request, has no session tracking, and has no event store; it
   therefore cannot promise that existing subscription continuity survives across requests.
   Session mode is the compatibility default. Stateless mode is suitable only if the product
   contract explicitly narrows remote MCP to request/response tools and fresh resource reads.

4. **Stdio and HTTP coexist without migration.** The stdio proof process and HTTP proof process
   were live in the same test run, each constructing its own server from `build_server()`. They
   share no port or transport-global state. Existing `.mcp.json -> bh-mcp` registrations therefore
   remain valid and should stay untouched. The daemon adds an opt-in URL registration for clients
   that need it; it must not replace or silently rewrite the stdio entry. Stdio keeps process-
   inherited trust and cwd. The daemon has a stable workspace/HQ root and cannot infer a remote
   caller's intended hive from cwd, so remote hive selection must be explicit.

5. **Snapshot then named-SSE resume is mechanically sound.** A snapshot returns its own bead
   revision plus `event_cursor: evt-1`. A subsequent event request with `Last-Event-ID: evt-1`
   returns only `id: evt-2 / event: bead.delta` and `id: evt-3 / event: run.activity`
   (`proofs/...:116-154`; `tests/...:162-189`). `after=` is the non-header fallback; conflicting
   header/query cursors return 400, while an expired cursor returns 409 with `action: resnapshot`.
   This proves sequencing and framing, not retention or source semantics.

6. **Streaming cancellation and shutdown coexist with MCP traffic.** The test holds an operator
   SSE response open, successfully lists MCP tools concurrently, closes the SSE client, and
   observes the generator's `finally` block within a five-second bound (`tests/...:243-266`). It
   then sends SIGTERM, requires the Uvicorn/FastMCP lifespan to finish within ten seconds, and
   verifies a post-lifespan marker (`tests/...:91-107,267-268`). No orphan listener remained.
   Native SIGTERM status is accepted after the graceful marker, matching bh's existing native-
   signal convention.

7. **Auth scopes can be enforced before protocol routing.** The proof's outer ASGI middleware
   maps `/mcp` to `mcp:control`, operator GET/SSE/OpenAPI to `operator:read`, activity POST to
   `activity:publish`, and `/ws/terminal` to `terminal:attach` (`proofs/...:29-93`). Real clients
   observed 401 for no token, 403 for a valid token with the wrong scope, 202 only with publisher
   scope, and a successful WebSocket handshake only with terminal scope (`tests/...:149-241`).
   `/health` is deliberately public and returns no inventory or secrets.

8. **CORS and network exposure must be explicit.** The proof binds only `127.0.0.1` and allows
   exactly one inert browser origin, with no wildcard and no credentialed CORS
   (`proofs/...:248-285`). The allowed origin received `Access-Control-Allow-Origin`; a different
   origin did not (`tests/...:206-217`). This is composition evidence, not production security.
   Plain HTTP/WS is acceptable only on loopback. Any non-loopback binding must be refused unless
   TLS is configured directly or a specifically trusted TLS reverse proxy is configured; the
   public schemes are then HTTPS/WSS. Forwarded headers must be ignored except from that trusted
   proxy. Bearer authentication is still required on loopback because browsers can reach
   loopback listeners.

9. **Full canonical hive identity can travel in the route, but routing must account for encoded
   slashes.** The real test requests `github%2Fbeadhive%2Fbeadhive`; Starlette has already decoded
   the slash before route matching, so the proof needs `{hive_id:path}`
   (`proofs/...:238-246`; `tests/...:162-173`). Product code must decode once, reject empty/dot
   segments, and perform an exact registry lookup. It must never infer a hive from a prefix,
   filename, request cwd, or partial path. A supplied `run_id` likewise resolves only by exact
   outer run ID.

10. **The terminal route belongs in this daemon; the terminal implementation does not.** A real
    scoped WebSocket client negotiated `bh-terminal.v1` beside active HTTP and MCP routes. This
    resolves `bh-lx6e.3`'s listener question: there should be one host listener and one lifecycle,
    with `/ws/terminal` composed here, not a second `bh serve` port. PTY ownership, resize,
    process-tree cleanup, container selection, and audit are downstream work and were intentionally
    represented by a placeholder only.

11. **This listener is a partial, not complete, container-plane entry point.** A container can use
    token-authenticated MCP/operator/terminal operations that the daemon itself exposes, and the
    host daemon can read its host-local HQ. It does not make the container's existing CLI/git
    bootstrap path HTTP-aware: HQ remote/sync remains SSH-only under `bh-pc2a.30`, and not every
    CLI operation has an HTTP equivalent. The implementation must either add an authenticated HQ
    bootstrap/sync API or continue provisioning SSH credentials. Calling `/mcp` a complete remote
    entry point before that is false.

## Verdict — **GO**

FastMCP 3.4.2 supplies the required `http_app` seam: every current MCP tool preserved exact
stdio/HTTP behavior, and one Starlette/Uvicorn process safely composed MCP, operator REST/SSE,
terminal WebSocket, OpenAPI, and health routes with one lifecycle and route-scoped auth.

The qualified GO is for **one unified host listener with sessionful MCP by default and the
browser API kept separate from MCP JSON-RPC**. It is not a claim that projections, auth, PTY
handling, supervision, telemetry, or remote HQ bootstrap are already implemented.

## Recommendation

`bh-u562.5` should ratify the following exact downstream contract and file its implementation
epic from it.

1. **Composition and ownership.** One per-user host daemon owns one Uvicorn/Starlette lifespan.
   Construct the existing server once, call:

   ```python
   mcp_app = build_server().http_app(
       path="/mcp",
       transport="streamable-http",
       stateless_http=False,
       json_response=False,
   )
   ```

   Compose its route objects with the operator and terminal routes, and enter
   `mcp_app.lifespan(app)` from the outer lifespan. The supervision mechanism is owned by
   `bh-u562.2`; daemon telemetry is owned by `bh-u562.4`.

2. **Stable routes and protocols.** Reserve exactly:

   | route | protocol/shape | required scope |
   |---|---|---|
   | `/mcp` | MCP Streamable HTTP; GET/POST/DELETE as FastMCP requires | `mcp:control` |
   | `/api/v1/factory` | JSON factory summary | `operator:read` |
   | `/api/v1/hives/{hive_id}/snapshot` | JSON snapshot plus source revision and event cursor | `operator:read` |
   | `/api/v1/hives/{hive_id}/events` | named SSE with opaque `id` | `operator:read` |
   | `/api/v1/runs/{run_id}/activity` GET | JSON snapshot/tail descriptor | `operator:read` |
   | `/api/v1/runs/{run_id}/activity` POST | append validated activity | `activity:publish` |
   | `/ws/terminal` | WebSocket subprotocol `bh-terminal.v1` | `terminal:attach` |
   | `/openapi.json` | OpenAPI 3.1 for non-MCP routes; MCP is referenced, not re-described | `operator:read` |
   | `/health` | minimal liveness/readiness, no inventory | public on the listener |

3. **Identity and context.** Pin one `GIT_WORKSPACE`/HQ root at daemon startup. Resolve each
   percent-encoded full hive identity by exact registry equality after one decode and path safety
   validation. Resolve activity by exact outer `run_id`. Never use daemon cwd as request identity.
   MCP tools that accept `hive` keep doing so; remote clients must supply it whenever the operation
   is hive-scoped.

4. **Session and resume.** Default MCP HTTP to session mode to preserve the existing resource-
   subscription/notification surface; cap idle sessions and terminate them during shutdown.
   Operator SSE has an independent opaque cursor namespace: snapshot first, connect with
   `Last-Event-ID` (or identical `after=` fallback), emit named/versioned events, return 400 for
   conflicting cursors, and return 409 `resnapshot` after retention loss. Never compare or combine
   MCP session IDs, bead revisions, event cursors, and outer run IDs.

5. **Compatibility.** Keep `bh-mcp` and existing `.mcp.json` stdio registration unchanged for at
   least the first daemon release. Offer HTTP as an additional explicit registration. Do not
   silently rewrite client configuration, redirect stdio through HTTP, or require the daemon for
   local CLI/MCP use.

6. **Security.** Authenticate in outer ASGI middleware before route handlers and enforce the four
   non-interchangeable scopes above. Use constant-time bearer verification, redacted audit logs,
   expiry/rotation, and explicit token audience. Bind loopback by default. Refuse non-loopback
   without TLS or a configured trusted TLS proxy; use HTTPS/WSS externally. Configure an exact
   CORS origin allowlist, never `*` with credentials, validate Host/Origin on browser transports,
   and do not trust arbitrary forwarded headers.

7. **Terminal and containers.** Move `bh-lx6e.3`'s terminal transport into this listener. Its
   implementation bead must define target selection, PTY resize, bounded buffering/backpressure,
   disconnect/cancellation, descendant cleanup, and audit under `terminal:attach`; it must not
   expose arbitrary unaudited container exec. Separately resolve `bh-pc2a.30`: either add the
   authenticated HQ bootstrap/sync operations needed by containers or document SSH provisioning
   as a remaining prerequisite.

8. **Shutdown and remaining risk gates.** On SIGTERM stop accepting new work, close MCP sessions,
   cancel SSE producers and terminals, flush telemetry, and exit within a configured bound. The
   implementation epic must test session exhaustion/DoS, slow consumers, cursor retention and
   resnapshot, proxy encoded-slash behavior, token revocation, daemon restart during an active MCP
   session, terminal process-tree cleanup, and simultaneous stdio/HTTP mutation races.

No proof file should be promoted directly into `src/`; the implementation should rebuild the
contract against product state readers, auth configuration, lifecycle ownership, and generated
OpenAPI.
