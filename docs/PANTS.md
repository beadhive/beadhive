# Pants developer foundation

Pants is an additive developer build graph. The canonical `uv.lock`, native `uv run pytest`,
`just check`, and `just check-all` commands remain authoritative. No selective validation route is
enabled by this foundation.

Install the official Pants launcher using the upstream installation instructions, then run it
from the repository root. `pants.toml` pins the engine to Pants 2.32.1, the first patch release
qualified by the Pants-first spikes. The launcher reads that repository pin and bootstraps the
matching engine rather than choosing a floating Pants version.

```console
pants version
pants generate-lockfiles --resolve=beadhive
pants test tests/unit/modules/config/test_resolution.py
pants package src/beadhive:bh
```

`3rdparty/python/beadhive.lock` and its required `.metadata` sidecar are generated by Pants'
experimental uv resolver. They are deliberately separate from canonical `uv.lock`; regenerate
them only through Pants after changing direct BUILD requirements, and commit both. The resolve
contains the repository pytest, pytest-xdist, and pytest-cov tools and Pants installs pytest from
that same resolve. Whole-lock execution avoids the mixed-distribution environment that previously
failed inside pytest's `_console_main` and omitted pytest-cov.

Python source and test generators create per-file targets. Pure-unit targets own root conftest and
watchdog diagnostics but omit `stateful_fixtures.py`; legacy tests own the stateful compatibility
plugin. Direct harness imports infer per-file harness dependencies. Package data and test fixture
resources have explicit resource targets. Unowned Python imports are errors, not warnings, so an
incomplete mapping fails closed during graph use.

The `bh` PEX is a graph/package smoke artifact, not a replacement installation format. Tests that
assume an installed `bh` console script beside `sys.executable`, dynamic fixture consumers, and
other unqualified boundaries continue to use native/full validation. Host cache placement,
capacity policy, and cross-worktree cache reuse are configured by the next adoption stage.
